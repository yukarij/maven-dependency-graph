# Сравнение со штатным Maven

Проверка выполнена 08.11.2026, Maven 3.9.9, Dependency Plugin 3.8.1,
JDK 25.0.2. Наши исходники компилировались с `--release 17`.
POM-файлы получены из https://repo.maven.apache.org/maven2.
Maven использован только как внешняя проверка, не внутри приложения.

Каждый исследуемый пакет добавлен единственной зависимостью
в отдельный вспомогательный проект `local:comparison:1`.
Затем выполнено:

```text
mvn -B -ntp -f pom.xml org.apache.maven.plugins:maven-dependency-plugin:3.8.1:tree
    -Dscope=runtime -Dverbose -DoutputFile=tree.txt
```

Это одна команда; перенос в примере нужен только для читаемости.
Локальный Maven-кеш вынесен за пределы сдаваемого репозитория.

| Пакет | Результат нашего приложения | Maven после удаления вспомогательного корня |
| --- | --- | --- |
| junit:junit:4.13.2 | -> org.hamcrest:hamcrest-core:1.3 | Совпадает, 2 вершины, 1 ребро |
| org.slf4j:slf4j-simple:2.0.16 | -> org.slf4j:slf4j-api:2.0.16 | Совпадает, 2 вершины, 1 ребро |
| org.hamcrest:hamcrest:2.2 | Нет зависимостей | Совпадает, 1 вершина, 0 рёбер |

Исходный вывод сохранён в `comparison/*-maven.txt` и `comparison/*-ours.txt`.
Файлы `ours` получены запуском финального приложения с тремя CSV-конфигурациями.
Для повтора: `run.bat examples/junit.csv`, аналогично slf4j.csv и hamcrest.csv.

Различие оформления: Maven показывает дополнительный вспомогательный корень,
тип jar и scope compile; наш граф использует groupId:artifactId:version.
После нормализации этих подписей расхождений по вершинам и рёбрам нет.

## Границы сравнения

Это сравнение трёх конкретных пакетов, а не доказательство полной
эквивалентности Maven Resolver. Реализован граф объявленных неoptional
compile/runtime-зависимостей с фиксированными версиями, с родителями,
properties, dependencyManagement и BOM imports.

В этой учебной реализации отсутствуют профили, метаданные SNAPSHOT,
диапазоны версий, classifier-aware разрешение, exclusions и выбор одной
версии по правилу nearest-wins. Scopes фильтруются локально по каждой POM,
а не распространяются по полной таблице транзитивности Maven.
Optional-зависимости не включаются даже у корневого пакета.
При конфликтах версий граф может содержать обе версии как разные вершины.
Локальные POM-зависимости с явно заданной версией перекрывают management;
переопределение в корне версий транзитивных пакетов не моделируется.
Вложенные объявления plugins/build не являются рёбрами графа.

Такие различия с Maven нужно объяснить при выборе других пакетов.
На трёх сохранённых примерах эти ограничения результата не меняют.
