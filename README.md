# Практическая работа №2, вариант 26

Визуализатор графа зависимостей Java (Maven). Реализация на Java 17+,
только стандартная библиотека JDK. Все настройки читаются из CSV.

## Этап 1: конфигурация

Сборка и запуск: `run.bat examples/test.csv` (Windows),
`sh run.sh examples/test.csv` (Linux/macOS). Нужен JDK 17+, а не только JRE.
При необходимости установите JAVA_HOME на каталог своего JDK.
Скрипт компилирует исходники в игнорируемую папку build.

Тесты: `test.bat` или `sh test.sh`. Тесты написаны на Java,
выполняются с `-ea`, не требуют JUnit и доступа к сети.

CSV содержит ровно четыре уникальных ключа, без строки заголовка:

| Ключ | Значение |
| --- | --- |
| package | Имя A-Z в тестовом режиме, иначе groupId:artifactId:version |
| repository | Путь к описанию графа либо HTTP(S) URL Maven-репозитория |
| test_mode | true или false |
| ascii_tree | true или false |

Относительный путь к тестовому репозиторию отсчитывается от CSV-файла.
Пустые, повторяющиеся, неизвестные ключи и некорректные значения запрещены.
Ошибки выводятся в stderr; код завершения 1, успешный запуск возвращает 0.
На первом этапе выводятся четыре настройки в формате ключ=значение.

## Функции

Config.load читает и проверяет настройки, Csv.parse разбирает CSV,
Coordinate.parse проверяет координаты, Coordinate.pomPath строит путь POM.
Main.execute запускает приложение, Main.main обрабатывает ошибки.
Описание назначения методов также дано в Javadoc исходных файлов.

## Этап 2: прямые зависимости Maven

Пример: `run.bat examples/junit.csv` скачивает POM по URL репозитория
и выводит прямые зависимости. `run.bat examples/test.csv 1` показывает
только параметры первого этапа. Сеть для первого этапа не нужна.

MavenRepository.dependencies получает POM и разрешает родителей и BOM
явным стеком. PomModel.read объединяет свойства и зависимости,
PomModel.expand раскрывает ${property}, PomModel.direct получает
координаты прямых зависимостей. Xml.parse запрещает DTD и внешние ресурсы.
Dependency.managed подставляет dependencyManagement. Maven и сторонние
библиотеки внутри приложения не вызываются. Ошибки HTTP, XML,
неразрешённых свойств и версий не скрываются.
